# 验证码登录与自动签到会话复用实施计划

目标：按已确认方案接入学校图片验证码，人工验证一次后默认账号与自动签到复用认证会话；认证失效或被拒绝时停止自动重试。

架构：保留现有 React、Node/TypeScript、got CookieJar；新增短期内存验证码挑战，客户端只持有随机挑战标识和图片，账号密码、Cookie、execution 均留在后端。默认账号采用共享认证协调器，防止网页与定时任务并发重复登录。

约束：不新增环境变量，不持久化密码或学校 Cookie，不输出认证令牌；遵守用户要求，实施中不新增或运行单元测试，完成后统一验证。不引入新的 UI 库，沿用现有表单样式。

- [x] 认证层：解析真实表单和动态验证码配置，展示图片；同一 CookieJar 继续提交；区分验证码、凭据拒绝、网络错误。挑战 5 分钟失效、最大 32 个，提交期间不可重复使用，刷新轮换标识。
- [x] 服务与调度：新增验证码提交/刷新接口，默认账号认证共享与互斥；自动签到在需人工验证时暂停，人工成功后复用上下文恢复；不因普通签到拒绝反复认证。
- [x] 网页：默认账号和手动账号均可显示验证码、刷新、提交；日历展示后台等待验证并可返回登录页。
- [ ] 交付：统一构建、类型检查、现有检查和模拟学校完整 HTTP 流程验证；真实站点只验证验证码出现及后台停止重试，不猜测或自动识别验证码。代码审查后提交，按已授权仓库流程发布并部署。

重点验证：挑战过期和并发重复提交、刷新后旧标识失效、账号间隔离、默认账号前后台共享、凭据错误不会无限重试、错误输出不泄露秘密。真实密码是否有效以及课程签到最终成功仍需用户完成学校验证码后确认。

验证记录：完整构建、后端类型检查和前端 lint 通过；独立审查发现的登录 HTML 过期识别、提交后新增验证码、并发默认登录令牌失效三项均已修复，并经模拟学校真实 HTTP 集成流程验证通过。集成检查仅使用虚构账号，没有真实签到请求。
