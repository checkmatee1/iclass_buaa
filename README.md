> 支持校园网直连和 WebVPN。两种模式使用同一组统一认证账号与密码。

## 🛠️ 部署与打包指南

*注：原先的 Python 版本代码已迁移至 `python` 分支，全新版本请参考当前分支。*

### 1. macOS 本地运行

在项目根目录下运行以下脚本命令，会自动安装相关依赖：

在 macOS 终端中执行：

```cmd
chmod +x scripts/setup.sh
./scripts/setup.sh
```

脚本会安装根目录、客户端和服务端依赖，并可直接启动浏览器开发页面。

也可以手动执行：

```bash
npm install
cd client && npm install && cd ..
cd server && npm install && cd ..
npm run dev
```

`npm run dev` 会同时启动本地后端和 Vite 前端。启动后在浏览器访问 `http://127.0.0.1:4000`。

如需配置默认 VPN 用户，复制 `.env.example` 为 `.env`，填写以下变量：

```env
ICLASS_DEFAULT_STUDENT_ID=
ICLASS_DEFAULT_VPN_USERNAME=
ICLASS_DEFAULT_VPN_PASSWORD=
```

配置完成后，打开登录页会优先尝试默认 VPN 登录；未配置或登录失败时仍可手动登录。

配置了上述默认 VPN 用户后，Docker 后端会自动启用后台签到，无需保持浏览器打开：

- 仅在后台启动、北京时间跨日、重新认证或默认账号重新加载网页课表后刷新当天课程；不再定时刷新；
- 每门课程上课前 20 分钟开始尝试签到；
- 每 60 秒尝试一次，签到成功后立即停止；
- 网络失败至少间隔 60 秒重试；会话失效后重新登录，遇到验证码或认证拒绝时暂停等待人工处理；
- 到课程结束时间仍未成功时停止，并在 Docker 日志中记录失败；
- Docker 服务重启后会重新读取 `.env` 并恢复调度。

可在 `.env` 中设置 `AUTO_SIGN_ENABLED=false` 临时关闭自动签到。运行状态可通过后端 `/api/health` 的 `data.autoSign` 字段查看。

### 2. Windows 本地运行

```cmd
./scripts/setup.bat
```

### 3. 构建检查

当前项目只通过浏览器运行，不提供桌面窗口或安装包。需要检查前端和服务端构建时运行：

```bash
npm run build
```

## 学校图片验证码与后台认证

点击“登录我的账号”或使用统一认证账号密码登录时，如果学校要求图片验证码，页面会显示验证码并等待人工输入。选择“换一张”后旧验证码立即失效；挑战保存在后端内存中，5 分钟过期，服务重启后需要重新登录。

默认账号完成验证后，网页与后台自动签到复用同一认证上下文，不再每 6 小时主动重复认证。学校会话实际失效后才重新登录；遇到验证码或认证拒绝时，后台暂停重试，日历显示提示。返回登录页，点击“登录我的账号”并完成验证即可恢复。普通课程尚未开放签到等拒绝不会触发重新认证。

验证码仅人工输入，不自动识别。Cookie、密码和 execution 不返回网页、不写入持久化存储或日志。默认配置仍使用原有字段，无需新增环境变量。

学校会话实际过期时，课表与签到接口返回 `401 SESSION_EXPIRED`，清除对应旧会话；网页显示具体原因并提供重新登录入口。默认账号下次认证会重新登录，后台遇到验证码时暂停等待人工验证，无需重启服务。网络故障和课程尚未开放签到不会因此触发重新认证。
